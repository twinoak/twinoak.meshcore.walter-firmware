## What is new

- A measurement session now ends *restored* instead of *stuck*: the radio is restarted by its reset line after a flash, which stops the scanner's own watchdog from resetting the repeater a minute into the health check that follows. Every flash of a radio ends that way now. Seen on simulators only — the one session this has been through on a board is the one that went wrong.
- A scanner's measurement lines no longer go missing while a step runs: nothing is sent to the server between a step's command and its end, the port holds four times as much, and a step that lost bytes all the same says so with the step's result. Seen in the simulator only: not yet on a board.
- When a claim's answer goes missing on the way back, the unit now asks the server once more in the same wake instead of leaving the work until the next one, and a job it is handed again is never run twice: the result it kept is sent instead. Tested against a scripted server only; not yet on a board.
- A unit now takes work until there is none left or the battery says stop, instead of two jobs an hour: a full battery allows eight helpings of work in one wake, a middling one four and a low one the one it always took. What it did and why it stopped is on its own line at the cable and in the unit's log. Seen against a simulated server only, not yet on a mast.
- A unit whose reset line does not reach its radio can now flash it all the same: the chip is asked whether it has a reset pin at all, and an image a pulse did not start is started over the debug port instead. `rak swd id` and `rak watch` say what this unit's line is. Tested on the host against a simulated radio with a dead line; no board with one has been flashed yet.

**Which repeater firmware this goes with.** A unit is two boxes and one key signs both: this
release runs beside
[`twinoak.meshcore.repeater-firmware` v0.1.2](https://github.com/twinoak/twinoak.meshcore.repeater-firmware/releases/tag/v0.1.2),
key `73efdd383a957596`. Nothing in the box link changed with this release, so a radio at that
release needs nothing done to it.

**Taking it from the release before, over LTE.** *Offer a release* on the unit's page on
meshmaster.dk with the Walter's product, then *Apply the candidate*; the unit fetches it on its
next check-in, writes it into its other slot, switches, and is brought back by the bootloader if
the trial fails. A unit that will not come up at all goes by cable, with the factory image and the
`esptool` line below.
