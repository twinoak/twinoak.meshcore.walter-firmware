## What is new

- A radio running the scanner can now be told what to measure from the console: `rak say sweep` prints the scanner's answer and then every line it sends for the next five seconds, whole — a sweep of the band is thousands of bytes and was shown cut before. Tested on the host against a simulated scanner; not yet on a board with a radio.
- A unit on a mast can now be given a scanner image from the server, not only over a cable: an offer may say it is for the scanner slot, and the candidate is left alone. An offer for a file the unit already holds is answered at once, without downloading it again. Tested on the host against a scripted server; no offer of either kind has been made to a board yet.
- `rak session 30 sweep` turns the radio into the scanner, runs one measurement and puts the repeater back and proves it — about forty minutes, and the repeater comes back by itself even if the board restarts or the cable is pulled in the middle. Tested against simulators only; not yet on a board.
- A measurement session can now be started from the server instead of over a cable: the radio becomes the scanner, runs up to six measurements, and comes back as the repeater, with the scanner's lines arriving on the job's page as each step finishes. A board that restarts in the middle still reports how it ended. Tested on the host against a scripted server; not yet on a board.
- A unit no longer restarts in the middle of a job it has taken on: a wake now stays awake for as long as the jobs it claimed were leased for, and a job it cannot finish is reported to the server instead of being left to expire. Two jobs were lost that way in one night in November. Seen in simulation only, not yet on a board or on a mast.
- A unit now starts with about twelve kilobytes more of its memory free: the table it reads a release's description with was sized for releases far larger than any that is published. A release of more than six images, or of more than five files in one image, is refused with a line saying which bound it broke. Seen in the host tests and in the heap model, not yet on a board.
- A measurement session can now keep a whole minute of a scanner's readings instead of about thirteen seconds of them: the unit uses 64 kB of the module's spare memory for them, where it had 8 kB of its own. A unit without that memory, or whose memory does not answer, works exactly as before. `heap room` on the console proves it. Not yet on a board.
- A unit no longer sends the adverts it heard twice: a batch the server took but could not answer for goes out again under the same id after a sleep. A console reply now belongs to the line that asked for it, so a configuration read cannot show one key's value under another, and a map of regions can be loaded into a repeater again. Tested against simulators only; not yet on a board.
- A unit now says when a batch of adverts is still waiting for the server's answer: `agent obs` and the unit's report name it, say how many adverts it holds and since which wake it has been waiting, and say nothing at all while the posts are being answered. Tested against simulators only; not yet on a board.

**Which repeater firmware this goes with.** A unit is two boxes and one key signs both: this
release runs beside
[`twinoak.meshcore.repeater-firmware` v0.1.2](https://github.com/twinoak/twinoak.meshcore.repeater-firmware/releases/tag/v0.1.2),
key `73efdd383a957596`. Nothing in the box link changed with this release, so a radio at that
release needs nothing done to it.

**Taking it from the release before, over LTE.** *Offer a release* on the unit's page on
meshmaster.dk with the Walter's product, then *Apply the candidate*; the unit fetches it on its
next check-in, writes it into its other slot, switches, and is brought back by the bootloader if
the trial fails. A unit that will not come up at all goes by cable, with the factory image and the
`esptool` line below.
