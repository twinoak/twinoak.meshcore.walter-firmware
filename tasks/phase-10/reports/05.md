# p10-05 — The fetch says who it is

meshmaster.dk refuses every `/agent/v1` request that does not carry `X-Agent-Version` with a 400
(`AgentV1.RequireVersionHeaderAsync`). The agent's calls have always carried it. **The download
never did, in any release up to and including v0.1.2** — `core/update/fetch.cpp` sent the token and
a `Range` and nothing else — so no release of either box could be fetched over LTE from this
server. Job 22841, 8 November 2026, failed in two seconds with *a status this firmware does not act
on*: a sentence that named neither the 400 nor the manifest.

Both halves of that are fixed here. The header is now **the client's own**, added to every request
it makes, so that no path above it can be written that forgets it; and a status that refused a
request is named by the status and the file, with the server's own sentence after it.

`tools/verify.ps1` is green on this machine, every step, on the final tree.

## Every request this firmware makes

Everything that reaches `interfaces::Http` goes through `core::net::Client`, and there are four
callers of it. `Host`, `User-Agent` (`core::banner()`: the product and the version), `Accept: */*`
and `Connection: close` are the request writer's on every request (`core/net/http1.cpp`) and are
left out of the table.

| What | Where | To | Headers it sends |
|---|---|---|---|
| the agent's seven calls: `GET /config`, `POST /heartbeat`, `/observations`, `/jobs/claim`, `/jobs/{id}/result`, `/extend`, `/progress` | `agent/modem_uplink.cpp`, `call()` | `server.url` | **`X-Agent-Version`** (its own, the version its owner gave it = `core::version()`), `Accept: application/json`, `Authorization: Bearer <server.token>`, `Content-Type: application/json` on a POST |
| `agent probe` at the console | `agent/uplink_probe.cpp` → `fetchConfig()` | `server.url` | the same: it is one of the seven |
| a release's `manifest.json` and `manifest.json.sig` | `core/update/fetch.cpp`, `fetchInto()` | `server.url` (an offer's `{server.url}{base}`) or any base URL the console's `fetch` was given | **`X-Agent-Version`** (the client's), `Authorization: Bearer` **when the caller passed a token** — the agent's offer does, the console's `fetch` does not |
| every **range** of the file | `core/net/download.cpp`, `fetch()` | the same host | **`X-Agent-Version`** (the client's), `Range: bytes=a-b`, `If-Range` after the first range, `Authorization: Bearer` when the caller passed one. Four of four `kMaxRequestHeaders` |
| `http get <url>` at the console | `core/console/console.cpp`, `httpGet()` | any host a person types | **`X-Agent-Version`** (the client's) and nothing else: **no token**, as before |

And the one thing that reaches `server.url` and is **not** a request: the self-update trial's third
condition (`core/update/tls_check.cpp`) opens a TLS connection to the configured host and port,
verifies the chain and closes it. No HTTP, no header, nothing to change; the test now holds that.

Nothing else in this firmware opens a connection of its own: the modem's certificate slots are
written with AT commands (`core/net/trust.cpp`), the wall clock takes the server's time out of the
`/config` and heartbeat replies, and the link to the radio is a UART.

## Deviations from the spec or the task

- **The task asks only for *a status this firmware does not act on* to be replaced; every
  status-derived sentence was replaced.** The acceptance criterion is *a refused request names its
  status and its file*, and the 401, 403, 429 and 5xx sentences named the status but not the file.
  They now read `http 403 for manifest.json: the server refused this unit`, through the same one
  function, rather than four different shapes. No test or document held the old strings.
- **`Result::why` is no longer always static text.** It is the client's own buffer for a status
  that refused the request, and the next refused request on the same client overwrites it. Every
  caller reads it before making another request (the fetch returns at once; `runOffer` writes it
  into the result; the console prints it), and `core/net/client.h` says so where `why` is declared.
  The one place that keeps a `why` beyond a call — `WakeCycle`'s `StepRecord::why` — is given
  `update::describe(verdict, own_image)`, which is static, and was already.
- **The fake does not model meshmaster.dk's exemption, on purpose.** Its `DownloadsWithoutAVersion`
  (task 4.28-177) serves the three download routes to a request with no header, for the units
  already in the field. The fake refuses **every** unversioned `/agent/v1` request, because the
  exemption is temporary — it goes the day no unit reports a version older than 0.1.3 — and a fake
  that modelled it would let this very mistake through again. `agent_version_required = false` is
  there for a test of the rule itself and is used by none.
- **The agent's uplink keeps its own `X-Agent-Version`.** The client fills the header in unless the
  caller named it, so `ModemUplink` is unchanged in that respect: its version is its owner's
  (`main/` passes `core::version()`), `agent url` prints that one, and the host tests give it a
  version of their own to prove the route. Two sources that agree in the firmware, and the client
  guarantees the header is there whatever the caller does.
- **`ModemUplink`'s error for a status it has no clause for** was `http <status>` and is now the
  client's sentence, which says the same thing and more. Its 401, 403, 429, 5xx and redirect
  clauses are untouched, because they carry things the client does not know (`Retry-After` as the
  library wants it, *the token was refused*).

## Decisions taken without asking

1. **The header goes in the client, not in the fetch.** The task names
   `core/update/fetch.cpp` and `core/net/download.cpp` as the places that lack it. Adding it in
   both would have fixed today's bug and left the next caller free to forget: the download's own
   ranges are a second place already, and the console's `http get` a third. One place that cannot
   be bypassed is the whole point of the task's own *and the reason it went unseen*. The cost is
   that the client knows a header name meshmaster.dk chose; `kVersionHeader`'s comment says why.
2. **A download from a host that is not `server.url` carries the header too** (the task left this
   to me). It does, for two reasons. It discloses nothing: `User-Agent` has carried the same
   product and version on **every** request since task p3-02, so a release on github.com already
   learns this unit's version. And a rule with an exception is a rule that can be got wrong — the
   client would have to know which host is `server.url`, which it does not and should not. The
   token's rule is unchanged and is the one that matters: a redirect that leaves the host drops the
   credential, and the console's `fetch` of a release on github.com carries none.
3. **A caller's empty version header is dropped rather than passed on.** Two headers of the same
   name reach ASP.NET as `a,b`, and an empty one plus the client's would have read as a version
   that is not this build's. The client owns the header; a caller that has nothing to say does not
   get to say nothing.
4. **A `detail` that holds the credential is dropped whole, not trimmed.** No server of ours echoes
   an `Authorization` header into a problem body, but the sentence reaches a job's posted `reason`
   and a console line, and a half-redacted token is a token. Both the whole header value and the
   part after the scheme word are looked for; the test gives the fake server both shapes.
5. **The 416's words are held at the download.** A fetch cannot reach a 416 without a store that
   holds more bytes than the server's file — a fixture of its own, for a sentence the download
   composes. The download's 416 keeps its meaning (*the server's file is shorter than the manifest
   promised*) with the client's `http 416 for <file>` in front of it, which is the only place this
   firmware overrides the client's sentence for a status.
6. **A problem body is read by its `detail` member and not by its content type.** A server that
   answers `application/problem+json` is the case this is for, but a 418 whose body happens to
   carry a `"detail"` is no worse off for being read, and requiring the content type would add a
   wanted header to a request that already carries four.
7. **The refusal is 200 bytes.** A job's `reason` and a console line both hold it; 200 is the
   console's own line cut (task p9-04) and leaves the `Call::error` of the agent's seam (128) to
   cut it further, which it does with a precision rather than silently.
