# p8-04 — The radio known before a job

6 November, on the first unit: `agent wake` with no `rak hello` before it ran a job for the unit's
**own** repeater as an ordinary mesh job, and the association's discover went out on the air from
the radio to itself. The local door (`LinkMesh`, `job_.local`) is armed only once
`Identity::refresh()` has the radio's key, and that needs a `HELLO` in this boot: a timer wake's
step 2 opens one, the console's `agent wake` opened none, and the boot's banner said so.

Two things are now true of **every** wake, timer or console, and each is one of the two halves the
`phase-6/FOLLOWUPS.md` item asked for ("open the session and read the identity before it runs a
job, **or** refuse a job it cannot yet tell is local" — both, because they fail in different
places):

- **The session.** `Identity::open()` (`components/agent/identity.cpp`): one `HELLO` when there is
  none, then the §5.6 read, then the key handed to the local door and the §7 drain.
  `AgentBackend::run()` calls it before `loop.wake()`, so it is before the heartbeat and therefore
  before the claim. A timer wake, whose step 2 has the session open, asks nothing extra.
- **The list.** `LinkMesh::supports()` now needs the own key as well as the session's `MESH_CLIENT`
  bit. The heartbeat's `jobTypes` is what meshmaster.dk routes by, so a unit that cannot tell a
  local job from a stranger's advertises **no mesh type** and the server sends none: the job is
  never claimed, rather than claimed and then refused with a lease nobody honours. The four
  `twinoak.*` types are unaffected — they need no key.

And the fake was taught the server's rule, which is what hid the fault from the host tests:
`MeshMasterScript` handed over whatever a test queued, so a wake that advertised no mesh type could
still be seen running a mesh job. It now routes a claim — and `jobsWaiting` — by the last
heartbeat's own `jobTypes`.

## Deviations from the spec or the task

- **The task's deliverable 1 says "Take the supervisor's own step if it fits, rather than a second
  copy of it." It does not fit, and nothing of it was copied.** `Supervisor::step()` is not a
  `HELLO`: from idle it classifies a silence (§9) and can enter `kClimbing`, whose rungs are a
  reset pulse and a kill. A console `agent wake` — a command about a *server* — must not
  power-cycle the radio as a side effect, and the backend is handed no supervisor, so giving it one
  to call `step()` would have put the ladder behind `agent wake` and outside the wake cycle's own
  bound. What is shared instead is the *thing itself*: a `HELLO` through the link client, in one
  method (`Identity::open()`) called from one place, and a timer wake — whose step 2 **is** the
  supervisor's step — finds the session up and asks nothing. `core/cycle/duty_cycle.cpp`'s
  `readPower()` already opens a session the same way, for the same reason, and names it.
- **The list is reduced by a second condition, which deliberately costs a neighbour's job.**
  `supports()` is asked per type and not per peer, so without the key there is no answer that is
  right for both a neighbour and the unit's own repeater. Of the two wrong answers, advertising is
  the 6 November fault and not advertising costs one wake's worth of a neighbour's jobs on a unit
  whose radio is silent or has made no identity — jobs the server keeps for the next wake. The task
  asked for "the smallest deterministic rule" and for "never claim a job that would then be
  refused"; this is both, and `docs/ARCHITECTURE.md` says so beside the paragraph that explains why
  the list is otherwise *not* reduced by the local door's table.

## Decisions taken without asking

- **`Identity::open()` lives on `Identity`, not on the backend.** It is the object that owns the
  link client and the rule "nothing is asked of a radio with no session"; `refresh()` keeps that
  rule unchanged for the console's `agent id`, which must stay free.
- **One `HELLO` and no more.** A radio that does not answer is *silent*, which is an outcome and
  not an incident. Classifying a silence and climbing the ladder stay the supervisor's.
- **A timer wake whose step 2 found the radio silent still spends one more `HELLO`.** One path was
  kept rather than a branch on `known.wake.radio`: the cost is the link's three tries on a UART in
  a wake that has just paid for an LTE attach, and after a rung that power-cycled the radio an ask
  that finds the radio back is worth more than the tries it costs. The knowledge to skip it is
  already in `BackendKnowledge::wake.radio` if the bench says otherwise — a follow-up line.
- **`IdentityProbe::identity()` hands the key over too.** `agent id` already refreshes the
  identity; after the `supports()` change a console that printed `job types (13)` while the local
  door was still shut would print a line the next heartbeat contradicts. So the one invariant is
  *whenever the identity is read, the local door follows* — the backend before every wake, the
  probe on `agent id`. This also keeps `rak hello` then `agent id` truthful on a unit that has not
  woken yet.
- **`context.radio_silent` and the §7 drain are taken from the session as it stands after the ask**,
  not from `known.wake.radio` / `known.radio.known` alone, which are what step 2 found a step
  earlier. That is what makes the console's `agent wake` — which runs no step 2 and carries no
  health — behave as a timer wake does.
- **The scripted meshmaster.dk routes by `jobTypes` by default**, and `jobsWaiting` counts only
  jobs it would route. `route_by_job_types = false` is there for a test that wants a server which
  misbehaves. Every job the existing tests queue is a `twinoak.*` one, which is always advertised,
  so no test changed meaning.
- **The shim's `fake::FakeMesh::setSelfKey` arms the link's own key.** The library's 46 runner
  scenarios are compiled unchanged, and they hand the exit node's own key over with `setSelfKey`;
  on a Walter the unit *is* its repeater (S-1), so that is the key the local door compares. The
  scenarios' target repeater has a different key, so every one of their jobs stays a mesh job. The
  two rigs of `test_heartbeat_body.cpp` hand the key over the same way the backend does, and the
  one case that has no key now also asserts `"jobTypes":[]`.
